## Usage

```jsx
import { Command, useCommandCollection } from "@chakra-ui/react"
```

```jsx
<Command.Provider>
  <Command.Dialog>
    <Command.DialogTrigger />
    <Command.DialogContent>
      <Command.Root>
        <Command.Label />
        <Command.Control>
          <Command.Indicator />
          <Command.Input />
          <Command.ClearTrigger />
        </Command.Control>
        <Command.List>
          <Command.Loading />
          <Command.ItemGroup>
            <Command.ItemGroupLabel />
            <Command.Item>
              <Command.ItemText />
              <Command.ItemCommand />
            </Command.Item>
          </Command.ItemGroup>
          <Command.Separator />
          <Command.Empty />
        </Command.List>
        <Command.Footer />
      </Command.Root>
    </Command.DialogContent>
  </Command.Dialog>
</Command.Provider>
```

`Command.Root` renders the search and results inline. For a palette, put it in
`Command.DialogContent` inside `Command.Dialog`: it closes after a command runs,
and has no global shortcut, so you can bind `⌘K` with the tool your app already
uses (see [Store](#store)).

Use `useCommandCollection` to rank items as the user types, and share it with
`Command.Provider`. The dialog clears the query after it closes.

```tsx
const command = useCommandCollection({ initialItems: commands })

<Command.Provider value={command}>
  <Command.Dialog>
    <Command.DialogContent>
      <Command.Root>{/* ... */}</Command.Root>
    </Command.DialogContent>
  </Command.Dialog>
</Command.Provider>
```

Inline, pass it to `Command.Root` with the `command` prop instead.

By default the command runs actions: give an item an `onSelect` to run it, and
no selected state persists. Set `closeOnSelect: false` on an item, or on `Root`,
to keep the dialog open. For a picker with a persistent selection, use
[Combobox](/docs/components/combobox) or [Listbox](/docs/components/listbox).

### Coming from cmdk

| cmdk                            | Chakra UI                                          |
| ------------------------------- | -------------------------------------------------- |
| `<Command>`                     | `<Command.Provider value={command}>`               |
| `<Command.Input>`               | `<Command.Input>` + `useCommandCollection`         |
| `<Command.List>`                | `<Command.List>`                                   |
| `<Command.Item onSelect={fn}>`  | `{ label, value, onSelect: fn }` in the collection |
| `<Command.Group heading="...">` | `<Command.ItemGroup>` + `ItemGroupLabel`           |
| `<Command.Empty>`               | `<Command.Empty>`                                  |
| `<Command.Dialog>`              | `<Command.Dialog>`                                 |

The key difference: `cmdk` owns the items and filters them from the DOM, while
here the items are data. `useCommandCollection` ranks them with fuzzy matching
and keywords, loads them asynchronously with `load`, or you replace the ranking
with `filter`.

### Inline

or popover.

### Groups

and `ItemGroupLabel`. Results are ranked within each group, and the group order
stays fixed while typing.

<ExampleTabs name="command-with-groups" />

### Toggle Items

Set `closeOnSelect={false}` and toggle values in `onSelect` to pick several
items without closing. Show a check on the items that are on.

### Controlled

item that matches.

<ExampleTabs name="command-controlled" />

### Controlled Search

Pass `query` and `onQueryChange` to `useCommandCollection` to sync it with
external state, URL params, or analytics.

<ExampleTabs name="command-controlled-search" />

### Store

An alternative way to control the command is to use the `RootProvider` component
and the `useCommand` store hook. The store lives outside the dialog, so the
search survives closing it, and you can read its state from anywhere, like
showing the last search next to a `⌘K` trigger.

<ExampleTabs name="command-with-root-provider" />

### Keywords

Add `keywords` to an item to make it findable by other words, like "preferences"
for Settings. Keyword matches rank slightly below label matches. Pass `filter`
to `useCommandCollection` to replace the ranking entirely.

<ExampleTabs name="command-with-keywords" />

### Prefix Search

Start the query with `>`, `@`, or `#` to scope the search to commands, people,
or channels. Backspace on an empty input clears the scope.

<ExampleTabs name="command-with-prefix-search" />

### Highlight Matches

Set `highlight` on `ItemText` to emphasize the characters that matched the
query, including fuzzy and camelCase matches.

```tsx
<Command.ItemText highlight>{item.label}</Command.ItemText>
```

### Hotkeys

Register the same items with `useHotkeys` so their shortcuts work with the menu
closed. Give an item a `scope` to make its shortcut, and its row in the menu,
available only in that part of the app. Format shortcuts per platform with
`useFormatHotkey`.

<ExampleTabs name="command-with-hotkeys" />

### Nested

Use `useCommandPages` for nested pages. Give an item a `parent` to place it on
that item's page. Selecting an item with children opens its page, and going back
restores the query that page had.

Escape in the dialog goes back a page before closing. Pass `onInputKeyDown` to
the input so Backspace on an empty input goes back too.

```tsx
const command = useCommandPages({
  initialItems: [
    { label: "Change status...", value: "status" },
    { label: "Done", value: "status:done", parent: "status" },
  ],
  deepSearch: true,
})

<Command.Provider value={command}>
  <Command.Dialog>
    <Command.DialogContent>
      <Command.Root>
        <Command.Input onKeyDown={command.onInputKeyDown} />
        ...
      </Command.Root>
    </Command.DialogContent>
  </Command.Dialog>
</Command.Provider>
```

Use `command.pages` to render a breadcrumb and `command.setPage` to jump to a
page. With `deepSearch`, a query also matches items in nested pages; use
`command.getPath(item)` to show where each match lives.

<ExampleTabs name="command-nested" />
