## Usage

```jsx
import { CommandPalette, Portal } from "@chakra-ui/react"
```

```jsx
<CommandPalette.Root>
  <CommandPalette.Trigger />
  <Portal>
    <CommandPalette.Backdrop />
    <CommandPalette.Positioner>
      <CommandPalette.Panel>
        <CommandPalette.Label />
        <CommandPalette.Control>
          <CommandPalette.Indicator />
          <CommandPalette.Input />
          <CommandPalette.ClearTrigger />
        </CommandPalette.Control>
        <CommandPalette.List>
          <CommandPalette.Loading />
          <CommandPalette.ItemGroup>
            <CommandPalette.ItemGroupLabel />
            <CommandPalette.Item>
              <CommandPalette.ItemText />
              <CommandPalette.ItemCommand />
              <CommandPalette.ItemIndicator />
            </CommandPalette.Item>
          </CommandPalette.ItemGroup>
          <CommandPalette.Separator />
          <CommandPalette.Empty />
        </CommandPalette.List>
        <CommandPalette.Footer />
      </CommandPalette.Panel>
    </CommandPalette.Positioner>
  </Portal>
</CommandPalette.Root>
```

To setup the command palette, use `useListCollection` to manage the
[list collection](https://ark-ui.com/docs/collections/list-collection), and
`useFilter` to filter the items as the user types.

By default the palette runs commands. Add `onSelect` to an item to execute its
action; the palette closes after the action and no selected state persists. Set
`closeOnSelect={false}` on a root or item when an action should keep the palette
open. To build a picker where selection persists, set `selectionMode` to
`single` or `multiple`.

The palette is a dialog. `Root` owns the open state and binds `⌘K` (`Ctrl+K` off
macOS) by default. Use `hotkeys={["mod+k", "mod+p"]}` for alternatives, pass
`hotkeys={[]}` to opt out, or configure editable targets and default prevention
with `hotkeyOptions`. When multiple palettes register the same shortcut, the
most recently mounted enabled palette handles it. `Trigger` is optional.

Search is wired through `onInputValueChange` on `Root` rather than an `onChange`
on the input, so filtering stays in one place.

### Coming from cmdk

| cmdk                            | Chakra UI                                         |
| ------------------------------- | ------------------------------------------------- |
| `<Command>`                     | `<CommandPalette.Root collection={collection}>`   |
| `<Command.Input>`               | `<CommandPalette.Input>` + `useFilter`            |
| `<Command.List>`                | `<CommandPalette.List>`                           |
| `<Command.Item onSelect={fn}>`  | `<CommandPalette.Item item={item} onSelect={fn}>` |
| `<Command.Group heading="...">` | `<CommandPalette.ItemGroup>` + `ItemGroupLabel`   |
| `<Command.Empty>`               | `<CommandPalette.Empty>`                          |
| `<Command.Dialog>`              | `<CommandPalette.Root>` is already a dialog       |

The key difference: `cmdk` owns filtering and ranking internally, while the
command palette treats data as userland. You own the collection and how it
shrinks — swap in fuzzy matching, server search, or debouncing without fighting
a built-in filter.
